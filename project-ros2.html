Voice-Enabled Human-Robot Interaction System

A real-time voice interaction pipeline for human-robot communication, integrating Whisper ASR, RASA, and TTS in a modular ROS2 architecture.

Python ROS2 Whisper ASR RASA TTS Ubuntu Speech Processing

Overview

This project builds a real-time voice interaction system that lets a person talk to a robot naturally — speak, get understood, and get a spoken response — running entirely on a modular ROS2 architecture on Ubuntu Linux.

Problem

Real-time speech pipelines on ROS2 are notoriously prone to race conditions and blocking calls: a slow ASR callback can freeze the executor, or two nodes reading/writing shared state simultaneously can produce inconsistent behavior — both of which break the responsiveness a natural voice interface depends on.

Approach

Whisper handles automatic speech recognition, RASA manages dialogue understanding and response selection, and a TTS engine speaks the response back — each running as a separate ROS2 node in a modular architecture. To eliminate race conditions, callbacks were organized under a timer-driven MutuallyExclusiveCallbackGroup, serializing access to shared resources instead of letting nodes race each other. Voice activity detection (VAD) was calibrated to reliably detect when the user starts and stops speaking, so the pipeline knows exactly when to start listening and when to hand off to RASA.

Results

The callback architecture achieved zero race conditions in practice, and the full pipeline — from spoken input through ASR, dialogue management, and TTS output — runs as a reliable real-time interaction loop.

Challenges

VAD thresholds that worked well in one room/microphone setup would misfire in another, so calibration had to be tuned rather than hardcoded. The bigger structural challenge was coordinating ASR, dialogue, and TTS nodes without any of them blocking the shared ROS2 executor — solved by the timer-driven MutuallyExclusiveCallbackGroup design rather than ad-hoc locking.
